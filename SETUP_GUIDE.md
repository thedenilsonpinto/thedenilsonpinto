## 1 · Put it on GitHub

Your profile README lives in the public repository named exactly like your username:
**`thedenilsonpinto/thedenilsonpinto`**.

1. **Let the workflows commit** (do this first). Repository → **Settings → Actions → General →
   Workflow permissions → Read and write permissions → Save.**

2. **Replace the old files.** With git:

   ```bash
   git clone https://github.com/thedenilsonpinto/thedenilsonpinto.git
   cd thedenilsonpinto
   git rm -r -q .                      # clears the old README + assets (history is kept)
   # now copy EVERYTHING from this folder in here, including the hidden .github/ folder and .gitignore
   git add -A
   git commit -m "The Midnight AI Lab: black + violet profile with an original vampire mascot"
   git push
   ```

   With GitHub Desktop: open the repo, delete everything in its folder, paste this folder's contents
   (turn on *show hidden files* so `.github` comes along), then **Commit to main → Push origin**.

3. **Check the first runs.** The push starts both workflows (**Actions** tab). *GitHub Pulse* replaces the five
   "awaiting first run" cards with your real numbers within about a minute, then refreshes them every night
   (18:17 UTC · 23:47 IST). If a run failed because step 1 wasn't done yet, open
   **Actions → GitHub Pulse → Run workflow**.

> **Old history.** `git rm` removes the old files from the current version, but earlier commits (including the
> previous avatar made from your photo) stay in the repository's history. To remove them from history too, make
> a fresh repository instead: delete `thedenilsonpinto/thedenilsonpinto` on GitHub, create it again (public,
> same name), then `git init`, add these files, commit and push.

## 4 · The character: the Midnight AI Vampire

**Original.** He was designed for this profile from your written brief only. He isn't based on any real
person, and he isn't a copy of any existing fictional vampire or any copyrighted design.

**The master design** (`assets/vampire/model-sheet.svg`): tall and elegant, about eight heads high · pale,
moonlit skin · a sharp jaw and high cheekbones · black, slightly messy swept hair · subtly pointed ears ·
dark-violet glowing eyes · small fangs · a long black gothic coat with a high standing collar and violet satin
lining · a silk cravat over a brocade vest · silver chain, clasps, buttons and ring · **a violet gemstone at
his throat, his signature** · violet rim light from the moon.

**One rig, every scene.** `forge/vampire/mascot.py` draws him as a 2D vector rig: one head, one costume and
one set of proportions, posed through joint angles. Every chamber therefore shows exactly the same character.
Poses: stand · hero · shadow · holo · portal · sorcerer · commander · timekeeper · scholar · guardian · walk ·
awaken · coder · final (plus a silhouette variant). Expressions: calm · smirk · fangs · intense.

**Powers** (`forge/vampire/chamber.py`, `scenes.py`, `sheet.py`):
01 shadow manipulation · 02 AI hologram · 03 data absorption · 04 file-teleportation portal · 05 code control ·
06 time control · 07 knowledge vision · 08 GitHub energy (decorative only) · 09 digital clones ·
10 void teleportation.

**Reusing him.** Every file in `assets/vampire/<scene>/` is the character with that scene's power on a
transparent background: drop it into slides, a portfolio site or a banner. To add a pose, add an entry to
`POSES` in `mascot.py` (shoulder / elbow / wrist angles per arm, hip / knee per leg), then call
`M.figure(doc, "your-pose")`.

**Why vector art and not a painted, AI-generated character?** No image-generation credits were available
while this was built (the connected Higgsfield account showed 0 credits), so he is drawn procedurally in code:
cinematic lighting, rim light, fabric shading, glowing eyes and gem. If you later commission or generate a
painted version, keep it original and use `model-sheet.svg` as the brief so it stays the same character.

## 6 · The config block

The comment at the very top of `README.md` controls everything that isn't a fact. Edit a value, commit, and
**Summon the Midnight AI Lab** rebuilds the SVGs and README for you (about a minute).

| Key | What it changes |
|---|---|
| `GITHUB_USERNAME` | repo links, the pairing QR code, stats, snake |
| `DISPLAY_NAME`, `TITLE` | hero, about, terminal, footer, alt texts |
| `SPECIALTIES`, `SPECIALTIES_2` | the two specialty lines in the hero |
| `TAGLINE`, `TAGLINE_2` | the two typed hero lines (the second also closes the footer) |
| `STATUS` | the pill under the hero taglines |
| `EMAIL`, `LINKEDIN_URL` | contact panel + buttons (leave one empty to hide it) |
| `RESUME_ANALYZER_DEMO`, `CYBER_DETECTIVE_DEMO`, `TECHNOVA_SITE` | LIVE DEMO / LIVE SITE buttons and pills (empty = hidden) |
| `FLASHDROP_BUILT`, `FLASHDROP_IN_PROGRESS` | module states on the FlashDrop map (next section) |
| `PRIMARY_COLOR` … `LAVENDER_COLOR` | the palette (6-digit hex); the validator only accepts violets and neutrals |

The palette from your brief: black `#020203` · near-black `#050507` · deep violet `#12091C` `#1A0D26` ·
purple `#241137` · violet `#6D28D9` `#7C3AED` · electric violet `#8B5CF6` · lavender `#C4B5FD` · white `#F5F3FF`.

## 7 · Marking FlashDrop progress

Every module shows **PLANNED** until you say otherwise, so nothing unfinished is ever presented as done:

```
FLASHDROP_BUILT       = FlashHub, FlashSend
FLASHDROP_IN_PROGRESS = FlashReceive
```

Built modules get a solid outline, in-progress ones pulse, planned ones stay dashed. Names must match:
FlashHub, FlashSend, FlashReceive, FlashGroup, FlashCloud, FlashAI. When FlashDrop gets a public repository,
add it to `PROJECTS` in `forge/vampire/data.py` like the others.

## 9 · Live GitHub stats

- **What:** contributions, commits, PRs, issues (last 12 months), stars, public repos, followers, current /
  longest / all-time streak, top languages (this profile repo is excluded so the forge's Python doesn't skew
  it), the contribution calendar and a violet contribution snake.
- **How:** GitHub's GraphQL API with the workflow's own `GITHUB_TOKEN` (public data only). If the API call
  fails, the job fails and yesterday's cards stay. No number is ever estimated. The glowing grid in the
  observatory panel is decoration and is labelled as such.
- **Private contributions (optional):** enable *Private contributions* on your profile and add a classic
  token with `read:user` + `repo` as the repository secret **`PULSE_TOKEN`**.
- **Heads-up:** GitHub pauses scheduled workflows after 60 days without repository activity. Re-enable it
  under **Actions → GitHub Pulse** if the nightly refresh stops.

## 10 · Local build & checks

```bash
pip install -r forge/requirements.txt       # fonttools, brotli, uharfbuzz, qrcode, pillow (pinned)
python forge/summon.py                      # rebuild every SVG + README (a few seconds)
python forge/summon.py --only vampire       # just the matching assets
python forge/validate.py                    # the same gate the workflows use
GITHUB_TOKEN=<token> python forge/github_pulse.py   # real stats locally (optional)
```

`validate.py` checks the config, that every README image exists and every `#anchor` has a target, that the
README only uses markup GitHub keeps, and that every SVG is well-formed with a `viewBox` and `<title>`, has no
scripts, event handlers or external references, and has **no colour outside black + violet**. It warns (but
doesn't fail) above 200 KB per SVG. The hero (it carries the castle painting) and the collapsed scene roster
are the two large ones.

## 13 · GitHub's limits → what was built instead

| Wanted | Limitation | Built |
|---|---|---|
| Castle image as the page background | a README can't style the page | the paintings are built into the hero, gate, footer and chamber windows |
| Animations | READMEs can't run JavaScript | CSS keyframes + SMIL inside every SVG (fog, bats, particles, shadows, typing, glowing eyes, portals) |
| Custom fonts | SVGs in READMEs can't load fonts | text converted to vector outlines at build time |
| Clickable cards | images have no links or hover | a button row under each card; nav buttons jump to anchors |
| Character moving between sections | images can't overlap | a scene in every chamber + two passage panels (void walker, teleportation) |
| Themed stats | third-party cards are generic or unreliable | own Action renders them in the Midnight AI Lab style |
| Dark & light theme | a README can't switch styles | every panel carries its own black ground |

Every SVG honours *reduced motion*, has a `<title>` + `<desc>`, and every README image has alt text.
Browsers pause off-screen animations, so each chamber starts moving when you scroll to it.
